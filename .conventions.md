# Repository naming conventions

## Member variables

Private and protected data members use **snake_case** with a **trailing underscore** (for example `key_`, `value_`).

Public accessors and methods do not use the trailing underscore (for example `get_key()`, `get_value()`).

## Types and classes

- Class names use **snake_case** in this project (for example `chained_bucket`, `node`).
- Type aliases in `common.h` use **PascalCase** (`Key`, `Value`) as established there.

## Configuration

- Set sizes once in `config.h` via `using MyConfig = store_config<KeySize, ValueSize>;`.
- Pass `MyConfig` (or another `store_config<...>`) as the template argument to `Store` and `HashFunction`.
- Wire buckets through `store_config`: `BucketTemplate` (default `addressed_bucket`), `StrategyTemplate` (default `linear_probing_strategy`).

## Files

- Public headers live under `include/WelfKV/`.
- Implementation sources live under `src/` when not header-only.

## Formatting

- Use **LF** line endings and **4-space** indentation (see `.editorconfig`).
- At most **one** blank line in a row; no blank line after every source line.
- Match the style in `node.h` / `bucket.h`: single blank line between include groups and between top-level declarations.
